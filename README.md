# SEO-дашборд: РУСКЛИМАТ и конкуренты

Статичный дашборд с данными из Keys.so. Открывается по обычной ссылке,
не требует сервера, базы данных и регистрации для зрителя.

## Как это устроено

```
Keys.so API  --(раз в 3 часа, GitHub Actions)-->  data/latest.json  -->  index.html (GitHub Pages)
```

1. `scripts/fetch.py` забирает отчёты из Keys.so по сайту и конкурентам
   и складывает их в один файл `data/latest.json`.
2. GitHub Actions запускает скрипт по расписанию и коммитит свежий JSON.
3. `index.html` + `assets/app.js` читают этот JSON и рисуют графики.
   Токен Keys.so в браузер не попадает и в коде страницы не хранится.

## Что на дашборде

- **Плитки сверху** — видимость (с местом среди всех доменов), запросы
  в топ-10, поисковый трафик, страницы в индексе, рекламный бюджет.
- **Рейтинг по видимости** — все домены отчёта горизонтальными полосами,
  от самых заметных к самым слабым. Сайт выделен синим.
- **Динамика видимости** — линии по месяцам по выбранным конкурентам.
- **Распределение запросов** — сколько запросов в топ-1 / 3 / 5 / 10 / 50.
- **Таблица «Сайт и конкуренты»** — полный список по группам.
- **Таблица запросов** — запросы сайта с позициями выбранных конкурентов,
  сортировка по любой колонке, поиск и фильтр «только где мы проигрываем».
- **Выбор конкурентов** — галочки по группам, влияют на графики
  и таблицу запросов. Рейтинг и таблица сравнения всегда показывают всех.

Переключатель в шапке меняет поисковую систему: Яндекс Москва (`msk`)
и Google Москва (`gru`).

## Настройка

### 1. Конкуренты

Всё в `config.json`. Домены сгруппированы, порядок групп задаёт порядок
блоков в таблице сравнения:

```json
{
  "site": "rusklimat.ru",
  "bases": ["msk", "gru"],
  "groups": [
    { "id": "marketplaces", "title": "Маркетплейсы и крупные магазины",
      "domains": ["dns-shop.ru", "vseinstrumenti.ru", "lemanapro.ru", "mvideo.ru"] },
    { "id": "close", "title": "Близкие по ассортименту и размеру",
      "domains": ["lunda.ru", "santech.ru", "mircli.ru"] },
    { "id": "niche", "title": "Меньше по размеру, но заметны в топе",
      "domains": ["master-water.ru", "tavago.ru", "vent-style.ru", "..."] }
  ],
  "selected_by_default": ["lunda.ru", "santech.ru", "mircli.ru"]
}
```

- `groups` — единственное место, где перечислены конкуренты. Добавить или
  убрать домен — правится только здесь;
- `selected_by_default` — кого показывать на графиках и в таблице запросов
  при открытии. Остальные видны в рейтинге и таблице сравнения;
- `bases` — региональные базы Keys.so: `msk` (Яндекс Москва), `gru` (Google Москва);
- `keywords_per_domain` — сколько запросов тянуть по нашему сайту (50);
- `competitor_keywords` — по конкурентам запрашиваем до 100 запросов
  и оставляем только пересечение с нашими фразами.

### 2. Токен

Токен берётся из переменной окружения `KEYSO_TOKEN` и **никогда не пишется в файлы**.

Локально:

```bash
export KEYSO_TOKEN="ваш-токен-из-личного-кабинета-keys.so"
python3 scripts/fetch.py
```

На GitHub — репозиторий → Settings → Secrets and variables → Actions →
New repository secret, имя `KEYSO_TOKEN`.

### 3. Публикация

Подробная инструкция со скриншот-планом шагов и разбором частых ошибок — в файле
[`DEPLOY.md`](DEPLOY.md). Ниже — короткая версия.

1. Создайте репозиторий на GitHub и залейте туда эти файлы:
   ```bash
   git init
   git add .
   git commit -m "Дашборд"
   git branch -M main
   git remote add origin https://github.com/ВАШ-ЛОГИН/seo-dashboard.git
   git push -u origin main
   ```
2. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, папка `/ (root)`.
3. Settings → Actions → General → Workflow permissions → **Read and write permissions**
   (иначе бот не сможет закоммитить свежие данные).
4. Добавьте секрет `KEYSO_TOKEN`.
5. Actions → «Обновление данных дашборда» → Run workflow — первый запуск вручную.

Через минуту-две ссылка вида `https://ВАШ-ЛОГИН.github.io/seo-dashboard/` начнёт отдавать данные.

## Локальный просмотр

Браузер не даёт читать `data/latest.json` через `file://`, поэтому нужен
крошечный локальный сервер:

```bash
python3 -m http.server 8000
# и откройте http://localhost:8000
```

Посмотреть вид без токена Keys.so:

```bash
python3 scripts/make_demo.py   # демо-данные с пометкой ДЕМО
python3 -m http.server 8000
```

В шапке появится жёлтая плашка «ДЕМО-ДАННЫЕ» — признак, что это не реальные данные.

## Проверки

```bash
python3 scripts/validate.py    # целостность data/latest.json
node scripts/smoke.js          # прогон интерфейса в jsdom: таблицы, выборка, сортировка
node scripts/screenshot.js     # скриншоты реального рендера в docs/
```

`validate.py` запускается в Actions после каждого сбора. Отдельно он не считает
ошибкой пустые позиции у нишевого конкурента: если по нашим фразам домена нет
в топ-100, это норма, и в лог попадёт пометка, а не провал проверки.

## Расход API

Keys.so разрешает 10 запросов за 10 секунд. Скрипт держит паузу 0,6 с между
запросами и при 429 ждёт столько, сколько просит сервер.

При 20 доменах и 2 базах: 40 пар «домен + база» × 2 отчёта = **~80 запросов
за запуск**, примерно 1,5-2 минуты. 8 запусков в сутки — около 640 запросов в день.

## Обновление данных

Расписание — в `.github/workflows/update.yml`
(`cron: "0 0,3,6,9,12,15,18,21 * * *"`, время UTC, то есть каждые 3 часа по Москве).
Кнопка «Обновить» в шапке дашборда только перечитывает уже сохранённый файл
и в Keys.so не ходит.

Каждый снимок дополнительно сохраняется в `data/archive/`.

## Структура файлов

```
config.json                  настройки: сайт, группы конкурентов, регионы
index.html                   страница дашборда
assets/app.js                логика отрисовки
assets/style.css             оформление
assets/chart.umd.min.js      графики (локально, без CDN)
scripts/fetch.py             сбор данных из Keys.so
scripts/make_demo.py         генератор демо-данных
scripts/validate.py          проверка целостности данных
scripts/smoke.js             прогон интерфейса в jsdom
scripts/screenshot.js        скриншоты рендера
data/latest.json             текущий снимок данных
data/archive/                архив снимков
.github/workflows/update.yml расписание сбора
```

## Что стоит знать

- Ссылка на дашборд открыта всем, у кого она есть. В данных нет ничего
  закрытого, но и пароля на странице нет.
- Если Keys.so не ответил по какому-то домену, дашборд всё равно откроется:
  домен просто выпадет из графиков, а в подвале появится число несобравшихся отчётов.
- У нишевых конкурентов по части запросов позиций не будет — это ожидаемо:
  в таблице запросов такая ячейка остаётся прочерком.
- Keys.so отдаёт историю по месяцам, а не по дням, поэтому «Динамика видимости»
  строится по месяцам. Более частое обновление снимков даёт свежесть последней
  точки, но не новую детализацию графика.
