# SEO-дашборд: РУСКЛИМАТ и конкуренты

Статичный дашборд с данными из Keys.so. Открывается по обычной ссылке,
не требует сервера, базы данных и регистрации для зрителя.

## Как это устроено

```
Keys.so API  --(раз в 3 часа, GitHub Actions)-->  data/latest.json  -->  index.html (GitHub Pages)
```

1. `scripts/fetch.py` забирает отчёты из Keys.so по сайту и конкурентам
   и складывает их в один файл `data/latest.json`.
2. GitHub Actions запускает скрипт по расписанию и коммитит свежий JSON.
3. `index.html` + `assets/app.js` читают этот JSON и рисуют графики.
   Токен Keys.so в браузер не попадает и в коде страницы не хранится.

## Что на дашборде

- **Плитки сверху** — видимость, запросы в топ-10, поисковый трафик,
  страницы в индексе, рекламный бюджет. У части показателей — стрелка
  изменения к предыдущему снимку.
- **Динамика видимости** — линия по месяцам, сайт рисуется толще остальных.
- **Распределение запросов** — сколько запросов в топ-1 / 3 / 5 / 10 / 50.
- **Таблица «Сайт и конкуренты»** — сравнение ключевых метрик по доменам.
- **Таблица запросов** — запросы сайта с позициями конкурентов,
  сортировка по любой колонке, поиск по фразе.
- **Трафик и реклама / Страниц в индексе** — динамика по месяцам.

Переключатель в шапке меняет поисковую систему (Яндекс Москва / Google Москва
и другие регионы из `config.json`).

## Настройка

### 1. Конкуренты и регионы

Всё в `config.json`:

```json
{
  "site": "rusklimat.ru",
  "competitors": ["daichi.ru", "ballu.ru", "electrolux.ru"],
  "bases": ["msk", "gru"],
  "keywords_per_domain": 50,
  "trend_months": 12
}
```

- `competitors` — список доменов через запятую;
- `bases` — региональные базы Keys.so: `msk` (Яндекс Москва), `gru` (Google Москва),
  `spb`, `ekb`, `nsk`, `kzn` и другие;
- `keywords_per_domain` — сколько запросов тянуть по каждому домену
  (влияет на число и время запросов);
- `trend_months` — сколько последних месяцев истории показывать.

### 2. Токен

Токен берётся из переменной окружения `KEYSO_TOKEN` и **никогда не пишется в файлы**.

Локально:

```bash
export KEYSO_TOKEN="ваш-токен-из-личного-кабинета-keys.so"
python3 scripts/fetch.py
```

На GitHub — репозиторий → Settings → Secrets and variables → Actions →
New repository secret, имя `KEYSO_TOKEN`.

### 3. Публикация

1. Создайте репозиторий на GitHub и залейте туда эти файлы:
   ```bash
   git init
   git add .
   git commit -m "Дашборд"
   git branch -M main
   git remote add origin https://github.com/ВАШ-ЛОГИН/seo-dashboard.git
   git push -u origin main
   ```
2. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, папка `/ (root)`.
3. Settings → Actions → General → Workflow permissions → **Read and write permissions**
   (иначе бот не сможет закоммитить свежие данные).
4. Добавьте секрет `KEYSO_TOKEN` (см. выше).
5. Actions → «Обновление данных дашборда» → Run workflow — первый запуск вручную.

Через минуту-две ссылка вида `https://ВАШ-ЛОГИН.github.io/seo-dashboard/` начнёт отдавать данные.

## Локальный просмотр

Браузер не даёт читать `data/latest.json` через `file://`, поэтому нужен
крошечный локальный сервер:

```bash
python3 -m http.server 8000
# и откройте http://localhost:8000
```

Посмотреть вид без токена Keys.so:

```bash
python3 scripts/make_demo.py   # сгенерирует демо-данные с пометкой ДЕМО
python3 -m http.server 8000
```

В шапке появится жёлтая плашка «ДЕМО-ДАННЫЕ» — признак, что это не реальные данные.

## Проверки

```bash
python3 scripts/validate.py    # целостность data/latest.json
node scripts/smoke.js          # прогон дашборда в jsdom: таблицы, сортировка, графики
```

`validate.py` запускается в Actions после каждого сбора: если Keys.so вернул
пустой отчёт по домену, это видно в логах и в подписи графика, а не молча.

## Расход API

Keys.so разрешает 10 запросов за 10 секунд. Скрипт держит паузу 0,6 с между
запросами и при 429 ждёт столько, сколько просит сервер.

При 4 доменах и 2 базах: 8 доменов × 2 базы × 2 отчёта = 32 запроса за запуск,
примерно полминуты. При 8 запусках в сутки — около 260 запросов в день.

## Обновление данных

Расписание задано в `.github/workflows/update.yml` (`cron: "0 0,3,6,9,12,15,18,21 * * *"`,
время UTC, то есть каждые 3 часа по Москве — 03:00, 06:00 и так далее).
Меняется одной строкой. Кнопка «Обновить» в шапке дашборда только перечитывает
уже сохранённый файл и не ходит в Keys.so.

Каждый снимок дополнительно сохраняется в `data/archive/` — если понадобится
посмотреть динамику чаще, чем раз в месяц.

## Структура файлов

```
config.json                  настройки: сайт, конкуренты, регионы
index.html                   страница дашборда
assets/app.js                логика отрисовки
assets/style.css             оформление
assets/chart.umd.min.js      графики (локально, без CDN)
scripts/fetch.py             сбор данных из Keys.so
scripts/make_demo.py         генератор демо-данных
scripts/validate.py          проверка целостности данных
scripts/smoke.js             прогон интерфейса в jsdom
data/latest.json             текущий снимок данных
data/archive/                архив снимков
.github/workflows/update.yml расписание сбора
```

## Что стоит знать

- Ссылка на дашборд открыта всем, у кого она есть. В данных нет ничего
  закрытого, но и пароля на странице нет.
- Если Keys.so не ответил по какому-то домену, дашборд всё равно откроется:
  пустой блок просто останется пустым, а в подвале появится предупреждение
  с числом не собравшихся отчётов.
- Keys.so отдаёт историю по месяцам, а не по дням, поэтому «Динамика видимости»
  строится по месяцам. Более частое обновление снимков даёт свежесть последней
  точки, но не новую гранулярность графика.
